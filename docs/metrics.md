# Implemented metrics and analytical boundaries

**Incident count:** distinct canonical incident identifiers. An unresolved identity contributes zero until a resolution chooses an audited source row. The current exploratory population includes all report statuses; report status can be filtered. A missing incident classification contributes to `Unknown` rather than dropping the incident.

**Unit responses:** distinct incident–apparatus participations from complete comma-separated tokens, after exact alias mapping and within-incident deduplication. An incident with four units contributes one incident and four unit responses. Repeated exports do not add responses. Unit and company incident counts can overlap and must not be added to recover department totals. Source-reported first-arriving apparatus counts are incident counts, not response speed.

All cards, charts, tables, and exported CSVs use the same `Filters` function and database data version. Across dimensions filters use AND; multiple choices within a dimension use OR. A selected location detail adds an AND restriction to the location multi-select. In participation mode, a selected apparatus or company qualifies an incident when it participated, counts the incident once, and counts only matching unit responses. In first-arrival mode, selection qualifies by the source-reported first-arriving label; unit-response counts then include all participants in qualifying incidents. Empty dropdowns mean all values. `Unknown` can be selected for missing source categories.

Date boundaries use a start-inclusive, end-exclusive interval ending at local midnight following the selected end date. Hour ranges use start-inclusive/end-exclusive clock hours; `22:00–06:00` spans midnight. Identical enabled hour boundaries and one-sided hour selections are rejected. Weekdays, month, season, and year are based on the parsed source local wall time. Records with no usable local time are excluded only when a temporal filter is active. Every chart is labeled with the selected population and observed bounds; these bounds do not prove complete source coverage.

Category share is the category's count divided by the displayed selected group count. Incident, dispatch, property, shift, first-arrival, and time shares use selected incident denominators, except time panels use selected incidents with usable dates. Apparatus and company unit-response shares use selected unit responses. Company participating-incident shares use selected incidents and can sum above 100% across companies. Tables show every category; leading-category charts include an explicit `Other` remainder. Counts below the configured threshold of 10 carry a small-sample flag. No rate per staffed hour, available unit hour, or population is calculated because denominators are not verified.

Locations use distinct incident counts at normalized address identity. The heatmap plots only addresses with cached coordinates that pass consistency checks. Each address contributes its distinct incident count as a weight; for display, the weight saturates at ten incidents per address so common low-count addresses remain visible. Plotly blends nearby addresses within a 30-pixel radius at the current zoom. Hotter colors indicate greater concentration, rather than a count within a fixed geographic boundary. The mapping percentage is located selected incidents divided by all selected incidents. Unlocated incidents remain in non-map totals. Repeat-location candidates meet the configured threshold of five incidents in the active selection. This is not an official target-hazard designation.

Response durations and target attainment are unavailable because the project owner cannot access the necessary First Due timing reports. Missing duration data is never displayed as zero, failed performance, or an import defect. Future interval definitions in `BUILD_SPEC.md` are provisional and outside the current implementation.
